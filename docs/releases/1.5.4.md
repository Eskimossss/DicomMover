DicomMover 1.5.4 — автономная portable-сборка для Windows x64. Отдельная установка .NET не требуется.

Релиз объединяет изменения версий 1.5.1–1.5.4, накопленные после опубликованной версии 1.5.

## Новые функции

### Поддержка аппаратов с одинаковыми SOP Instance UID

В **Настройки → Папки** добавлен переключатель **«Игнорировать SOP Instance UID при поиске дубликатов»**.

- Файлы сравниваются по SHA-256 полного содержимого, а не по исходному SOP Instance UID.
- Разные снимки с одним исходным UID добавляются в очередь отдельно.
- Точная копия файла с другим именем повторно не добавляется.
- Изменение содержимого означает новый отпечаток. Отпечатки успешно отправленных файлов сохраняются после очистки истории.

### Исправление некорректных UID перед отправкой

Для каждой папки доступен отдельный переключатель **«Исправлять некорректные UID перед отправкой»**.

- Исправляются отсутствующие, некорректные или совпадающие с SOP Class UID значения SOP Instance UID `(0008,0018)`, Study Instance UID `(0020,000D)` и Series Instance UID `(0020,000E)`.
- Валидные идентификаторы сохраняются. SOP Class UID, обозначающий тип DICOM-объекта, не подменяется произвольным значением.
- Новые UID вида `2.25.*` зависят от содержимого исходного файла и постоянны при повторных отправках и перезапусках.
- При нулевых Study/Series UID каждый файл получает отдельное исследование и серию. Снимки разных пациентов не объединяются по ФИО или дате рождения.
- Исходный SOP Instance UID сохраняется в SQLite. Режим исправления фиксируется для записи очереди.
- Старые записи распознаются по прежнему ключу неизменённого файла с сохранением истории доставок.
- Проверка SHA-256 перед отправкой предотвращает отправку изменившегося файла под прежней идентичностью.

Оба переключателя по умолчанию выключены и настраиваются отдельно для каждой папки. Изменения выполняются в отправляемой копии: исходный файл и Pixel Data сохраняются.

## Исправлена работа с датами

- Фильтр Study Date `(0008,0020)` принимает `20260901` и `2026.09.01`.
- Дата, равная выбранному порогу, допускается к отправке.
- Оба формата учитываются в существующей очереди и мастере отправки истории.
- При включённом исправлении UID корректные даты DA с точками нормализуются в отправляемой копии: `yyyy.MM.dd` → `yyyyMMdd`.

## Обновлён интерфейс

- При первом запуске списки PACS и наблюдаемых папок пустые. Демонстрационные записи больше не создаются.
- Пустую конфигурацию можно сохранять; запуск мониторинга становится доступен после настройки папки и PACS.
- Кнопки во всех окнах получили светло-голубой фон, скруглённые углы и тонкую рамку.
- Невыбранные вкладки **«Очередь и история»** и **«Активные проблемы»** теперь имеют видимую окантовку.
- Фильтры **«Статус»**, **«PACS»** и **«Показывать»**, включая раскрытые меню, оформлены в том же голубом стиле.

## Как обновиться

1. Полностью завершите прежний DicomMover, включая значок в системном трее.
2. Расположите новый EXE в папке с существующими `appsettings.json` и `data`, либо перенесите эти файлы и папку в новый каталог. Для нестандартного относительного `DatabaseFile` сохраните заданное расположение базы.
3. Запустите DicomMover 1.5.4. Существующие настройки и история сохраняются.

Для нового запуска без прежней конфигурации папки и PACS добавляются вручную.
