# DicomMover

![Версия](https://img.shields.io/badge/version-1.3-blue)
![Платформа](https://img.shields.io/badge/platform-Windows-success)
![.NET](https://img.shields.io/badge/.NET-8.0-purple)

DicomMover — переносимая Windows-программа для автоматического поиска DICOM-файлов в локальных или сетевых папках и отправки их на один или несколько PACS по DICOM C-STORE.

Программа хранит очередь в SQLite, проверяет PACS через C-ECHO, восстанавливает незавершённую работу после перезапуска и защищает PACS от повторной отправки одного SOP Instance UID.

- несколько наблюдаемых папок и несколько PACS;
- отдельный выбор PACS для каждой папки;
- поиск в подпапках с обработкой недоступных каталогов без остановки всего сканирования;
- проверка завершения записи файла перед чтением и отправкой;
- проверка формата DICOM и перенос неподходящих файлов в `BAD`;
- отбор исследований начиная с заданной даты по Study Date `(0008,0020)`;
- отправка DICOM C-STORE и проверка доступности PACS через C-ECHO;
- постоянная очередь и история на базе SQLite;
- независимое состояние доставки на каждый PACS;
- дедупликация по SOP Instance UID `(0008,0018)`;
- автоматические и ручные повторные отправки;
- сохранение, удаление или архивирование исходного файла после успешной доставки;
- отображение ФИО пациента, модальности, статуса, ошибок и результатов каждого PACS;
- подробное окно DICOM-экземпляра;
- поиск, фильтры и настраиваемые столбцы;
- ежедневные журналы, резервные копии SQLite и очистка старых данных;
- автозапуск вместе с Windows, автоматический старт мониторинга и работа в системном трее;
- защита от запуска двух экземпляров программы;
- понятный экран первоначальной настройки и блокировка запуска до заполнения конфигурации;
- подтверждение удаления папок и PACS, а также предупреждение о несохранённых настройках;
- окно «О программе» с версией и расположением базы данных и журналов.

## Быстрая настройка

1. Откройте **Настройки → PACS** и добавьте принимающие серверы.
2. Для каждого PACS заполните IP, порт, Called AE и Calling AE, затем нажмите **Проверить C-ECHO**.
3. Откройте **Настройки → Папки**, добавьте источники DICOM и отметьте PACS, на которые должна отправляться каждая папка.
4. При необходимости задайте минимальную дату исследования и действие с файлом после успешной отправки.
5. Проверьте параметры во вкладках **Мониторинг**, **Журнал**, **Хранение** и **Запуск и интерфейс**.
6. Сохраните настройки и нажмите **Запустить мониторинг**. Перед ручным стартом программа проверит папки, каталог SQLite и выполнит настоящий C-ECHO каждого включённого PACS.

Если PACS не отвечает, программа покажет причину и позволит отменить запуск либо начать мониторинг с недоступным PACS. Файлы останутся в очереди до восстановления связи.

## Настройки папок

На вкладке **Папки** источники показаны списком слева. Параметры выбранной папки редактируются в карточке справа. Каждая папка является самостоятельным источником.

| Настройка | Назначение |
|---|---|
| **Вкл.** | Включает или отключает мониторинг папки без удаления её настроек. |
| **Название** | Понятное оператору имя папки. |
| **Путь** | Корневая папка, в которой появляются DICOM-файлы. |
| **Подпапки** | Разрешает рекурсивный поиск. Недоступная подпапка пропускается, остальные продолжают сканироваться. |
| **Исследования с даты** | Отправляет только файлы со Study Date `(0008,0020)`, равной или более поздней указанной дате. Пустое поле отключает ограничение. |
| **После отправки** | Действие после успешной доставки файла на все выбранные PACS: оставить, удалить или перенести в архив. |
| **Архив** | Папка назначения для режима «В архив». |
| **Сохранять подпапки** | Работает только в режиме «В архив»: в архиве воспроизводится структура каталогов относительно корня наблюдения. |
| **Удалять пустые подпапки** | Работает в режимах «Удалить» и «В архив»: удаляются опустевшие вложенные папки. Корневая папка не удаляется. |
| **PACS для папки** | Серверы, на которые должны отправляться файлы из выбранного источника. Можно отметить несколько PACS. |

Включённые корневые пути не должны пересекаться. Например, нельзя одновременно настроить `D:\DICOM` и `D:\DICOM\CT` как два источника. Для просмотра `CT` достаточно включить поиск в подпапках у `D:\DICOM`.

### Ограничение по дате исследования

Дата берётся из DICOM, а не из даты создания файла Windows. Например, значение `02.08.2026` пропускает Study Date раньше `20260802` и принимает `20260802` и более поздние даты.

Если ограничение включено, DICOM без корректного Study Date не отправляется. При изменении даты уже существующая очередь пересчитывается: ранее отфильтрованные записи могут снова стать доступными, если новая граница их допускает.

### Папка BAD

Если стабильный файл не удаётся прочитать как DICOM или в нём отсутствуют обязательные SOP Class UID/SOP Instance UID, он переносится в папку `BAD` внутри соответствующего корня импорта. `BAD` автоматически исключается из дальнейшего сканирования.

Если файл с таким именем уже существует в `BAD`, к новому имени добавляется временная метка. Ошибка доступа при переносе записывается в журнал.

## Настройки PACS

На вкладке **PACS** серверы показаны списком слева, а параметры выбранного сервера — в карточке справа.

| Настройка | Назначение |
|---|---|
| **Вкл.** | Включает PACS для проверки и отправки. |
| **Название** | Отображаемое имя PACS в интерфейсе и журнале. |
| **IP** | IP-адрес принимающего PACS. DNS-имя не используется. |
| **Порт** | DICOM-порт PACS. |
| **Called AE** | AE Title принимающей стороны. |
| **Calling AE** | AE Title DicomMover, предъявляемый PACS. |
| **Подключение, сек.** | Максимальное ожидание установления сетевого DICOM-соединения. После таймаута PACS считается недоступным. |
| **Отправка, сек.** | Максимальное ожидание завершения C-STORE одного DICOM-файла. После таймаута отправка считается неуспешной. |

AE Title должен содержать не более 16 символов. Доступность можно проверить кнопкой **Проверить C-ECHO**.

## Настройки мониторинга

| Настройка | Назначение |
|---|---|
| **Интервал проверки папок** | Пауза между циклами сканирования. Обычное значение — 45–120 секунд. |
| **Время стабильности файла** | Файл обрабатывается, когда он имеет ненулевой размер, доступен для чтения и с момента последней записи прошло указанное время. Это защищает от чтения недописанного DICOM. |
| **Максимум попыток** | Число неуспешных DICOM-отправок, после которого автоматические повторы прекращаются. По умолчанию — 5. |

Изменение настроек во время работы применяется через контролируемый перезапуск мониторинга. Фоновый поток всегда работает с отдельной неизменяемой копией конфигурации.

## Очередь, ошибки и повторные попытки

SQLite хранит файл, SOP Instance UID, DICOM-метаданные и отдельную доставку для каждого выбранного PACS. После перезапуска незавершённые записи остаются в очереди.

### Недоступен PACS или сеть

- PACS проверяется C-ECHO примерно раз в минуту;
- файл получает состояние ошибки ожидания, но счётчик попыток не увеличивается;
- ограничение в 5 попыток не расходуется;
- проверки продолжаются без ограничения до восстановления PACS или вмешательства оператора;
- после восстановления связи очередь отправляется автоматически.

### PACS доступен, но C-STORE завершился ошибкой

По умолчанию применяются повторы:

1. после первой ошибки — через 1 минуту;
2. после второй — через 5 минут;
3. после третьей — через 15 минут;
4. после четвёртой — через 30 минут;
5. после пятой — автоматические повторы прекращаются.

Кнопка и контекстное меню **Повторить отправку** сбрасывают счётчик неуспешных доставок и возвращают их в очередь. В подробностях можно повторить доставку только на выбранный PACS. Уже успешно отправленная доставка повторно не создаётся; это действие поясняется оператору и записывается в журнал.

### Статусы

- **Ожидает** — файл готов к обработке;
- **Отправляется** — выполняется C-STORE;
- **Отправлен частично** — хотя бы один PACS принял файл, но остались неуспешные доставки;
- **Отправлено** — все назначенные PACS подтвердили доставку;
- **Ошибка** — доставка ожидает повтора или исчерпала число попыток.

Цветной кружок слева является ненавязчивым индикатором статуса.

## Защита от дубликатов

После успешной отправки SOP Instance UID записывается в отдельный компактный реестр SQLite. Повторно обнаруженный DICOM с тем же UID не добавляется в очередь, даже если подробная старая запись уже удалена по сроку хранения.

Дедупликация действует на уровне DICOM-экземпляра, а не имени файла. Если требуется сознательно повторить неуспешную доставку, используйте команду **Повторить отправку**.

## Интерфейс оператора

- карточки сверху показывают количество ожидающих, отправленных и ошибочных исследований;
- цветная плашка показывает текущее состояние мониторинга;
- одна основная кнопка запускает или останавливает мониторинг;
- панель снизу показывает состояние отдельных папок и PACS;
- щелчок по элементу панели временно приостанавливает или продолжает конкретную папку/PACS; пауза действует до перезапуска программы;
- поиск работает по пути/имени файла, ФИО, UID, модальности и тексту ошибки;
- доступны фильтры по статусу и PACS;
- кнопка **Столбцы** скрывает и показывает колонки, выбранный состав и ширина сохраняются;
- двойной щелчок открывает подробности: SOP UID, путь, ФИО, Patient ID, дата рождения, модальность, Study UID, Accession Number, Study Date и результаты каждого PACS;
- **Очистить историю** скрывает выбранные записи из интерфейса, не удаляя DICOM-файлы немедленно;
- пустая очередь отображает отдельное информационное состояние;
- журнал можно свернуть, чтобы освободить место для очереди;
- сводка очереди показывает статистику за день.

## Журналирование

Журналы создаются по одному файлу на день:

```text
logs/dicommover-YYYY-MM-DD.log
```

В главном окне журнал можно отфильтровать по уровням **Все**, **Ошибки**, **Предупреждения** и **Информация**. Ошибки выделяются красным, предупреждения — оранжевым. Если журнал свёрнут, новое предупреждение или ошибка показывает красную метку **Новая проблема**; после открытия журнала метка сбрасывается.

Кнопка **Очистить** очищает только видимую область программы. Файл журнала остаётся на диске. Старые файлы удаляются автоматически по параметру **Хранить дневные файлы журнала**.

Опция **Записывать ФИО в журнал** по умолчанию выключена. Включайте её только с учётом правил обработки персональных и медицинских данных. В SQLite ФИО сохраняется для отображения очереди независимо от этой настройки.

## SQLite, резервные копии и хранение

При переносимом размещении рабочие данные находятся рядом с программой:

```text
appsettings.json          настройки
data/dicommover.db        очередь и история SQLite
logs/                     ежедневные журналы
backups/                  ежедневные резервные копии SQLite
```

- `busy_timeout` и внешние ключи устанавливаются для каждого соединения SQLite;
- перед важной миграцией старой схемы создаётся резервная копия;
- при запуске создаётся не более одной резервной копии БД за день;
- срок хранения резервных копий задаётся отдельно;
- старые успешно завершённые или скрытые подробные записи очищаются по сроку хранения SQLite;
- компактный реестр отправленных SOP UID сохраняется для дедупликации;
- опциональная еженедельная проверка выполняет `PRAGMA integrity_check` и `PRAGMA optimize`;
- настройки можно экспортировать/импортировать, а резервную копию SQLite создать вручную.

Для переноса на другой компьютер рекомендуется остановить мониторинг и использовать опубликованную Release-сборку, упакованную в ZIP. Не следует копировать весь каталог исходного проекта вместе с `bin`, `obj` и тестами: это создаёт лишние файлы и может превысить ограничение Windows/VMware на длину пути.

## Автоматическая работа

Параметры распределены по отдельным вкладкам:

- **Журнал** — подробное журналирование, запись ФИО и срок хранения дневных журналов;
- **Хранение** — срок отображения записей, срок истории SQLite, резервные копии и проверка целостности;
- **Запуск и интерфейс** — запуск вместе с Windows, автоматическое начало мониторинга, запуск свёрнутым и системный трей.

При завершении Windows программа отменяет текущую операцию, корректно возвращает незавершённую доставку в очередь и закрывает SQLite. Одновременно может работать только один экземпляр DicomMover.

## Разработка и сборка

Этот раздел нужен разработчикам, которые хотят изучить код, изменить программу или проверить свою версию. Для разработки требуются:

- Windows 10/11;
- .NET 8 SDK;
- Visual Studio 2022 либо командная строка .NET.

| Команда | Что делает |
|---|---|
| `dotnet restore` | Загружает зависимости NuGet, необходимые проекту. Программу не запускает и не устанавливает. |
| `dotnet build DicomMover.csproj` | Компилирует обычную Debug-сборку в локальную папку `bin\Debug\net8.0-windows`. Ничего не публикует в интернет. |
| `dotnet test DicomMover.Tests\DicomMover.Tests.csproj` | Компилирует приложение и тестовый проект, затем запускает автоматические проверки. |
| `dotnet publish ...` | Создаёт готовую Release-сборку в указанной локальной папке. На GitHub она автоматически не загружается. |

### Автоматические тесты `DicomMover.Tests`

`DicomMover.Tests` — отдельный проект с автоматическими тестами на xUnit. Он не входит в готовый EXE и нужен только при разработке. Другой разработчик может изменить DicomMover, добавить собственные тесты и проверить, что существующая логика не сломалась.

На момент выпуска 1.3 набор из 23 тестов проверяет, в частности:

- первый запуск и сохранение настроек;
- миграцию конфигурации старых версий;
- проверку интервалов и пересекающихся наблюдаемых папок;
- очередь, повторные отправки и восстановление незавершённой работы;
- дедупликацию по SOP Instance UID;
- фильтр Study Date и резервное копирование SQLite.

Запуск всех тестов:

```powershell
dotnet test DicomMover.Tests\DicomMover.Tests.csproj
```

### Локальная публикация portable-версии

Следующая команда создаёт автономный EXE для Windows x64 в папке `publish\DicomMover-1.3-win-x64` на текущем компьютере:

```powershell
dotnet publish DicomMover.csproj -c Release -r win-x64 --self-contained true `
  -o publish\DicomMover-1.3-win-x64 `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true
```

Папки `bin`, `obj` и `publish` являются локальными результатами сборки и исключены из Git. Чтобы приложить готовые файлы к версии на GitHub, их нужно отдельно загрузить в GitHub Release.
